# MovieEncoderForNissanNavi システム設計書（v1）

日産純正カーナビ **MM521D-L** で再生可能な MP4 へ、一般的な動画ファイルを一括変換する Windows 11 向けデスクトップアプリケーション。

---

## 1. 目的・スコープ

- ユーザーが複数の動画ファイルを D&D／ファイル選択で投入し、MM521D-L 互換の MP4 へ一括変換する GUI アプリ。
- **v1 は Windows 11 専用**。macOS は対象外（コードは macOS で詰まない書き方に配慮するが、ビルド・テスト・バイナリ同梱は行わない）。
- 動画変換エンジンは **ffmpeg（CPU / libx264）** を利用。GPU エンコードは v1 では非対応。

> ⚠️ **実機互換は未検証の前提**。MM521D-L 実機での再生確認はユーザー責任とする（手動チェックリスト参照）。出力プロファイル値はプリセット JSON で容易に変更できる構成にしている。

---

## 2. 技術スタック / 主要ライブラリ

| 領域 | 採用 | 備考 |
|---|---|---|
| ランタイム | Electron | Main/Renderer/Preload の 3 プロセス |
| UI | React + TypeScript | |
| 状態管理 | zustand | |
| D&D | react-dropzone | フォルダ D&D 対応（直下のみ） |
| 開発ビルド | electron-vite | main/preload/renderer を 1 設定で |
| 配布 | electron-builder | **`zip` ターゲットのみ**（ポータブル） |
| 変換エンジン | ffmpeg-static | CPU libx264。GPU 非対応 |
| メタ取得 | ffprobe-static | `-of json` で取得 |
| テスト | Vitest | ユニット中心＋lavfi 統合 |

### 重要な技術判断

- **`fluent-ffmpeg` は不採用**（メンテ終了）。`child_process.spawn` でffmpegを直接起動し、`-progress pipe:1` で機械可読に進捗取得、`kill` でキャンセル。
- **GPU エンコードは廃止**。`ffmpeg-static` の公式ビルドにはハードウェアエンコーダがほぼ含まれないため、CPU(libx264) のみとする。
- **配布はポータブル zip のみ**。`portable`（自己展開型）ではなく `zip` ターゲットを使い、exe と同階層を書込可能な実体フォルダとして利用する。

## 3. アーキテクチャ

```
┌─────────────────────────────┐         ┌──────────────────────────────┐
│ Renderer (React)            │  IPC    │ Main (Node.js)               │
│ - UI 表示                   │ <=====> │ - ffmpeg 実行 (spawn)        │
│ - ユーザー操作              │ preload │ - ファイル操作               │
│ - zustand store             │ bridge  │ - 変換キュー管理             │
│                             │         │ - 設定/プリセット読込        │
└─────────────────────────────┘         └──────────────────────────────┘
```

- **Main プロセス責務**: ffmpeg/ffprobe 実行、ファイル操作、キュー管理、設定永続化、OS 通知。
- **Renderer プロセス責務**: UI 表示とユーザー操作のみ（Node API へ直接触れない）。
- **Preload**: `contextBridge` で型付き API を `window.api` として公開。`contextIsolation: true`、`nodeIntegration: false`。

## 4. 出力仕様（Nissan 標準プリセット）

| 項目 | 値 |
|---|---|
| コンテナ | MP4（`-movflags +faststart`） |
| 映像 | H.264 (libx264) / High Profile / Level 4.0 / yuv420p |
| 解像度 | 1280×720（アスペクト維持・黒帯パディング） |
| フレームレート | 29.97fps（`30000/1001`） |
| 映像ビットレート | 平均 4000kbps 固定 |
| 音声 | AAC-LC / 48kHz / 128kbps |

参考 filtergraph: `scale=1280:720:force_original_aspect_ratio=decrease,pad=1280:720:(ow-iw)/2:(oh-ih)/2`

### プリセット一覧（読み取り専用 JSON、v1 では GUI 編集なし）

| プリセット | x264 preset | レート制御 | 音声 | 用途 |
|---|---|---|---|---|
| Nissan 標準 | medium | 平均 4000k 固定 | AAC 128k | 既定・互換重視 |
| 高画質 | slow | CRF 18 | AAC 192k | 画質優先（互換枠維持） |
| 高速変換 | veryfast | 4000k | AAC 128k | 速度優先 |
| Safe/Compat | medium | 2500k | AAC 128k | Main/Level3.1 フォールバック |

すべて 720p / 29.97fps / yuv420p / faststart は共通。Profile/Level/解像度など互換に関わる値は固定。

## 6. 機能仕様

### 6.1 ファイル登録
- **D&D 領域**（複数可）＋**「ファイルを選択」ボタン**併設（領域クリックでもダイアログ）。
- **フォルダ D&D 対応（直下のみ・再帰なし）**: ドロップしたフォルダ直下の対応拡張子のみ登録。サブフォルダは辿らない。
- 対応外拡張子は無視、重複ファイルは除外。
- 一覧は各行に削除ボタン＋「全てクリア」。削除は**待機中の行のみ**可（変換中は不可）。

### 6.2 メタ情報取得
- 投入直後に**非同期 ffprobe**（`-show_format -show_streams -of json`）。取得でき次第、解像度/コーデック/fps/再生時間を行に反映。
- ffprobe 失敗（破損等）でも**キューには載せる**。失敗行は「メタ取得失敗」表示。
- duration が取れない場合、進捗は不定モード。

### 6.3 出力先
- デフォルト = アプリフォルダ配下 `output/`（exe 同階層＝書込可）。
- **変換開始ボタン押下直後に、出力先選択ダイアログを必ず表示**（デフォルト上記、変更可）。
- 選択した 1 ディレクトリへ全ファイルを出力。
- **名前順＝ナビの表示順にする**: MM521D-L は USB メモリ（FAT）内のファイルを名前順ではなく**フォルダへ書き込まれた順**で表示する。並列変換では完了順がバラバラになるため、
  1. 各ジョブは OS の一時フォルダ（`%TEMP%/movie-encoder-for-nissan-navi-XXXX/`）へ変換する（状態「転記待ち」）。
  2. 全ジョブ終了後、**出力ファイル名順に 1 件ずつ直列で**出力先へ転記する（同一ボリュームはリネーム、別ボリュームはコピー→一時ファイル削除）。並び順はエクスプローラーと同じ（拡張子を除いた名前で比較、数字は数値として比較: `2` < `10`、`movie.mp4` < `movie (1).mp4`）。
  3. 転記後に一時フォルダを削除し、完了サマリを通知する。
- 停止した場合も、変換済み（転記待ち）のファイルは転記する。転記中の 1 件の失敗は他に波及させない。
- 出力先に**既存ファイルがある場合や過去にファイルを削除した場合**、新しいファイルは空いた位置に入るため、既存ファイルを含めた全体の並びは保証できない（全体を揃えるには出力先フォルダを空にしてから変換する）。

### 6.4 出力ファイル命名
- 拡張子を `.mp4` に変換。
- **衝突時のみ**括弧付きインデックス（`movie.mp4` → `movie (1).mp4` → `movie (2).mp4`）。
- 元ファイル・既存ファイルは**絶対に上書きしない**（入力パス＝出力パスでも必ずリネーム）。
- **一時ファイル方式**: 一時フォルダ内で一時名（`<final>.part`）で書き、**成功時のみ最終名へアトミックリネーム**。キャンセル/エラー時は一時ファイルを自動削除（壊れた出力を残さない）。出力先への転記時も既存ファイルは上書きせず、コピー失敗時は途中までのファイルを削除する。

### 6.5 変換キュー
- **同時実行数はユーザー指定可能（範囲 1〜8、デフォルト 3）**。
- 並列時は各ファイル行で個別進捗、ログはファイル名プレフィックス付きで混在表示。

### 6.6 進捗表示
- 状態: 待機中 / 変換中 / 転記待ち / 完了 / エラー / キャンセル。「転記待ち」は一時フォルダへの変換が済み、名前順転記を待っている状態（一覧から削除不可）。
- パーセンテージ・残り時間推定 = `out_time ÷ duration`（`-progress pipe:1` の `out_time_us` を使用）。

### 6.7 ログ
- ffmpeg の **stderr** を GUI に時系列で混在表示（ファイル名プレフィックス付き）＋ジョブ別フィルタ。
- 保存は**手動ボタン**で UTF-8 テキスト 1 ファイルにエクスポート（自動保存なし）。
- エラージョブの stderr 末尾は保持し、ダイアログ/ログに残す。

### 6.8 エラーハンドリング
- 事前チェック不要。事後捕捉（終了コード ≠ 0 ＋ stderr）でジョブをエラー扱いし、**他ファイルは継続**。
- stderr パターンからエラー種別を推定し日本語表示（容量不足／権限／破損／その他）。

### 6.9 キャンセル
- 変換中ジョブの停止（プロセス kill ＋一時ファイル削除）。
- キュー全体停止（実行中を kill、待機中は未着手）。

### 6.10 完了通知
- 全ジョブ終了時に「完了 N 件 / エラー M 件」サマリを**ダイアログ＋OS 通知**（Electron `Notification`）。
- ダイアログにエラー一覧（ファイル名＋推定理由）と「出力フォルダを開く」ボタン。
- キャンセルでキュー全停止した場合は「中止：完了 X 件」と区別。

### 6.11 設定永続化
- exe 同階層 `config.json`（書込不可なら `userData` にフォールバック）、自前の薄い実装。
- 保存項目: 同時実行数 / 最後に使った出力先 / 最後のプリセット / ウィンドウ状態。

## 7. UI

- **ライトモード固定**（ダークモードは v1 では非対応）、**日本語のみ**（文言は `i18n/ja.ts` に集約、i18n フレームワーク無し）。
- 画面構成:
  1. ツールバー（プリセット選択 / 同時実行数 / 変換開始 / 停止 / ログ保存）

  4. ログビューア（混在表示＋フィルタ）

## 8. IPC 設計

`window.api`（preload 経由、型は `shared/types`）:

| API | 方向 | 内容 |
|---|---|---|
| `probeFiles(paths)` | R→M | ファイル登録（フォルダ展開・拡張子フィルタ・dedup）＋メタ取得 |
| `pickOutputDir(default)` | R→M | 出力先選択ダイアログ |
| `startQueue(req)` | R→M | キュー開始（ジョブ一覧・出力先・プリセット・同時実行数） |
| `cancelJob(id)` | R→M | 個別ジョブ停止 |
| `cancelAll()` | R→M | キュー全停止 |
| `saveLog(text)` | R→M | ログをファイルへ保存 |
| `openPath(dir)` | R→M | 出力フォルダを開く |
| `getConfig` / `setConfig` | R→M | 設定の取得/保存 |
| `getPresets()` | R→M | プリセット一覧 |
| `onJobUpdate(cb)` | M→R | ジョブ状態/進捗イベント |
| `onLog(cb)` | M→R | ログ行イベント |
| `onQueueDone(cb)` | M→R | 完了サマリイベント |

## 9. テスト戦略

3 層構成（E2E なし）:

1. **ユニット（Vitest, CI 向き）**: 出力名生成＋衝突連番 / ffmpeg・ffprobe 引数組立 / `-progress` パース / stderr エラー種別推定。
2. **統合（ローカル, 実 ffmpeg）**: サンプル動画は同梱せず **lavfi**（`testsrc`/`sine`）で生成して入力に使用。日本語名・H.265 入力・AVI/MKV・キャンセル(kill)・出力先変更・4K 入力を検証。
3. **手動チェックリスト（README）**: 実機 MM521D-L 再生確認・UI 操作・通知など。

## 10. ビルド / 配布

- 開発: `npm run dev`（electron-vite）。
- ビルド: `npm run build` → `npm run dist`（electron-builder `zip` ターゲット, Windows x64）。
